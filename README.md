# sukisu内核挂载器

独立 Android root 工具，不依赖 LSPosed。解决 **SukiSU / KernelSU 等内核管理器场景下，用 Scene"转为系统应用"后 APK 无法挂载生效**的问题：识别 Scene 在 `/data/adb/modules` 创建的系统应用转换模块，以 tmpfs + 只读 OverlayFS 挂载 APK。支持 app、priv-app 目录和同目录 split APK。

## 下载

前往 [Releases](../../releases) 下载最新 APK（当前 **1.0.3**）。覆盖安装请沿用同一签名来源的版本。

## 版本历史

- **1.0.3**：应用名称统一为"sukisu内核挂载器"，用于桌面、系统应用信息、最近任务和应用内标题；沿用原包名与签名以支持覆盖安装。界面中"Scene"指用于创建转换模块的第三方应用。
- **1.0.2**：新增"取消选中挂载"。勾选已挂载应用后操作，完成后框架软重启。取消前要求 `/data/app` 中有保留的普通安装，并核对模块 APK 与系统目录版本。取消后先显示"待软重启回退普通应用"，重启扫描后按实际身份显示"普通应用"。支持撤销最近一次挂载或取消挂载。
- **1.0.1**：应用卡片显示"已挂载 / 未挂载 / 部分挂载"标签和 APK 挂载数量。以系统目录 APK 与模块 APK 的内容一致为准，单独显示包管理器识别的系统应用身份。点击刷新或完成挂载、撤销后更新。

## 使用

1. 在 Scene 应用管理中长按应用，选择"转为系统应用"，勾选"创建 Magisk 模块"，建议选 `/system/app`。
2. 打开本工具，在 KernelSU 中给予本工具超级用户权限。
3. 刷新，选择目标模块，点"挂载选中应用"。
4. 单独点击"框架软重启"，桌面恢复后重新打开工具核验状态。

只执行 `setprop ctl.restart zygote`，没有完整重启命令。原应用和数据保留；系统可能显示为 UPDATED_SYSTEM_APP，这是正常系统应用身份。完整重启后需重新挂载。此工具不安装元模块、不自动运行开机脚本。

取消挂载仅针对所选应用目录，以空的 tmpfs bind 视图屏蔽 APK，避免旧的叠加挂载再次露出系统 APK；底层挂载层和模块文件保留，因此可重新挂载或撤销。不卸载、不清除数据。效果限当前内核运行期，未自动禁用 Scene 模块；若其他元模块在下次开机重新挂载，还需在相应管理器中禁用它。

已有目录重新挂载时采用应用目录 bind，不增加 OverlayFS 堆叠深度；新增目录继续使用 OverlayFS。撤销核对本次内核启动 ID 和目标挂载 ID，只撤销本工具最近一次操作。已软重启识别的应用，撤销后需再次软重启更新身份。

## 适用范围

- 在 iQOO Neo9 / vivo V2338A、Android 16、SukiSU 4.2.1-r2 环境进行设备实测。
- 其他设备需要 root、nsenter、OverlayFS、可读的 Scene 转换模块；兼容性未逐机验证。
- 仅挂载 APK，不处理模块中的权限 XML、SELinux 规则、原生库或其他系统文件。priv-app 不等于平台签名，也不会自动获得全部特权权限。
- 只识别 Scene 标记的模块及 `system/app/目录/*.apk`、`system/priv-app/目录/*.apk` 标准布局。禁用或待删除模块不可选。
- 启动 Activity 对外公开；挂载、撤销、软重启没有导出的外部调用接口。应用没有网络权限。

## 构建

JDK 17+、Android SDK 35、Gradle 8.11.1、Android Gradle Plugin 8.7.3。编辑 `local.properties` 指向自己的 SDK，再执行 `gradle :app:assembleDebug`。发布 APK 使用本机 debug keystore 签名，供个人使用。后续覆盖安装应沿用同一签名（签名密钥不在仓库内）。
